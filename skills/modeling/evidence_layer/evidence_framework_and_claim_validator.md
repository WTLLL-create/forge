# 证据框架 + 声明验证器（Evidence Framework & Claim Validator）

> 从「模型有效」升级为「论文中每一条结论都有可验证的证据支撑」。
> 国赛评委最后打分的核心问题：你的结论凭什么可信？

---

## 一、证据金字塔

```
Level 4: 跨条件验证
  不同数据、不同场景、不同时间下的一致表现
  → 证明：结论具有普适性

Level 3: 消融+敏感性+统计检验
  每个改进组件有贡献、参数稳健、差异统计显著
  → 证明：结论不是偶然的

Level 2: 多模型对比+多指标
  与多个基线对比，在多个指标上评估
  → 证明：结论不是片面的

Level 1: 单次实验结果
  跑一次，一个指标，一个好数字
  → 证明：几乎什么都证明不了
```

| 论文类型 | 常见证据层级 | 得分对应 |
|----------|:---:|:---:|
| 校赛 | Level 1-2 | 60-70 |
| 省赛 | Level 2 | 70-80 |
| 国二 | Level 2-3 | 80-85 |
| 国一 | Level 3-4 | 85+ |

## 二、论文声明分类（Claim Taxonomy）

### C1：性能声明

**论文中的典型表达**：
- "本文方法具有更高的预测精度"
- "优化结果优于传统方案"

**需要的最小证据**：
- □ 至少 2 个基线对比（简单基线 + 标准基线）
- □ 至少 2 个评价指标
- □ 交叉验证或独立测试集
- □ 统计显著性检验（如配对t-test）

**如果缺失**：
→ 声称降级为"在本次实验条件下，本文方法的表现优于XXX"

### C2：稳定性声明

**论文中的典型表达**：
- "模型具有较强的鲁棒性"
- "对参数变化不敏感"

**需要的最小证据**：
- □ 关键参数 ±20% 扰动实验
- □ 多次运行（≥5次）的均值±标准差
- □ 不同数据子集上的表现一致性

**如果缺失**：
→ 声称降级为"在默认参数下模型表现正常"

### C3：创新声明

**论文中的典型表达**：
- "本文提出了一种改进方法"
- "创新点在于XXX"

**需要的最小证据**：
- □ 消融实验：去掉改进→性能退化X%
- □ 与未改进版本的系统对比
- □ 改进机制的物理解释（不只是"反正变好了"）

**如果缺失**：
→ 声称降级为"本文对标准方法做了定制化调整"

### C4：应用价值声明

**论文中的典型表达**：
- "可以指导实际决策"
- "具有推广价值"

**需要的最小证据**：
- □ 在至少一个不同场景下的表现验证
- □ 结果的实际可解释性（不能是黑箱输出）
- □ 明确标注适用范围和条件限制

**如果缺失**：
→ 声称降级为"在本题数据条件下有效"

## 三、声明强度-证据对照表

| 语言强度 | 关键词 | 最少需要的证据层级 |
|----------|--------|:---:|
| 推测 | "可能""或许" | Level 1 |
| 陈述 | "本文使用""结果表明" | Level 1 |
| 主张 | "有效""适用""提升" | Level 2 |
| 强主张 | "显著优于""明显改善" | Level 3 (需统计检验) |
| 普适断言 | "具有普遍性""可推广至" | Level 4 (需跨场景验证) |

**规则**：论文中的语言强度不能超过证据层级。Level 1 的证据不能用"显著优于"来表述。

## 四、声明验证器

### 自动检查规则

```
扫描论文中的每条结论性语句，检查：

1. 是否有对比对象？
   "本文方法更好" — 比谁好？→ 必须明确对比对象

2. 是否有定量差异？
   "明显提升" — 提升多少？→ 必须有数字

3. 是否有统计支撑？
   "显著优于" — 显著吗？→ 高频词要求p<0.05/交叉验证

4. 是否有适用范围？
   "普遍适用" — 什么条件下？→ 必须标注边界

5. 是否有证据引用？
   "如图X所示""表Y显示" — 图/表是否真的支持这个结论？
```

### 过度声称检测

| 论文中的话 | 检测问题 | 修正 |
|-----------|----------|------|
| "本文方法优于所有现有方法" | 对比了"所有"吗？ | "在对比的3个基线中，本文方法RMSE最低" |
| "模型具有极强的鲁棒性" | "极强"有证据吗？ | "参数±20%变化时目标值波动<5%" |
| "可以广泛应用于" | 在哪里验证了"广泛"？ | "在XX和YY两个场景下验证了有效性，适用条件为..." |
| "首次提出" | 确认过文献吗？ | 去掉"首次"，改为"本文提出" |

### 证据缺失修补

```
如果发现某条声明证据不足：
  → 不是删除声明
  → 而是降级语言强度
  → 或补充对应的实验（对接 Stage 23 实验引擎）
```

## 五、证据链完整性检查

```
对论文的核心结论（摘要中的1-2句），检查：

□ 理论依据：有没有数学推导/物理原理解释？
□ 实验证据：有没有定量实验结果？
□ 消融证据：如果是改进方法，每个改进有单独验证吗？
□ 对比证据：和至少一个基线比过吗？
□ 稳健证据：参数变了结论还成立吗？
□ 局限说明：诚实标注了什么情况下不成立？

六项全有 → 国一级别的证据完整性。
缺1-2项 → 国二级别。
缺3+项 → 省赛级别。
```

## 六、与已有系统的对接

```
Stage 26 贡献提炼 → 论文声明（C1-C4分类）
    ↓
本文件 → 扫描声明 → 检查证据 → 标记缺失
    ↓
Stage 23 实验引擎 → 补充缺失实验
    ↓
Stage 27.2 诊断 → 如果实验失败，诊断原因
    ↓
Stage 29 后续模块 → 消融/鲁棒/敏感/不确定性分析
```
