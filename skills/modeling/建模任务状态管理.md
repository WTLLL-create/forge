## 一、状态机概览

```
                        ┌──────────────────────────┐
                        │        FAILOVER           │
                        │  数据不足 → 回退到         │
                        │  模型失败 → 降级           │
                        │  验证失败 → 重选模型       │
                        └──────────────────────────┘
                                  ↑
                                  │ (异常时)
                                  │
INIT → ANALYSIS → MODEL_SELECTION → DATA_PROCESSING → SOLVING → VALIDATION → PAPER_GENERATION → DONE
  │        │            │                 │              │           │               │
  │        │            │                 │              │           │               │
  ▼        ▼            ▼                 ▼              ▼           ▼               ▼
读题     分析需求    选模型方法      清洗+特征工程    数值求解    验证指标       生成论文
```

## 二、各状态定义

### S0: INIT — 初始化

| 维度 | 内容 |
|------|------|
| **当前任务** | 读取题目文档，识别基本信息 |
| **输入** | 题目文件（.docx/.pdf）、附件数据（.xlsx/.csv） |
| **已完成步骤** | — |
| **缺失信息** | 全部待获取 |
| **下一动作** | 进入 ANALYSIS |
| **状态保持数据** | `{problem_file, attachment_files}` |

---

### S1: ANALYSIS — 需求分析

| 维度 | 内容 |
|------|------|
| **当前任务** | 理解题目诉求，提取关键信息 |
| **输入** | INIT 的题目文件 |
| **已完成步骤** | INIT |
| **缺失信息** | 具体求解方向、数据特征 |
| **下一动作** | 进入 MODEL_SELECTION |
| **状态保持数据** | `{problem_type, sub_type, keywords, data_characteristics, solution_level}` |

**调用**: `数学建模题型识别.md`

---

### S2: MODEL_SELECTION — 模型选择

| 维度 | 内容 |
|------|------|
| **当前任务** | 沿决策树行进，确定模型和方法 |
| **输入** | ANALYSIS 的问题类型和数据特征 |
| **已完成步骤** | INIT → ANALYSIS |
| **缺失信息** | 模型参数详细值 |
| **下一动作** | 进入 DATA_PROCESSING（如果需要）或直接 SOLVING |
| **状态保持数据** | `{model_name, selection_reasons, rejected_models, failover_model}` |

**调用**: `模型选择决策树.md`

**Checkpoint**: ⚑ 人工确认点 — 模型选择是否正确？是继续还是更改？

---

### S3: DATA_PROCESSING — 数据处理

| 维度 | 内容 |
|------|------|
| **当前任务** | 清洗数据、构造特征、输出 numpy 数组 |
| **输入** | 原始数据 + MODEL_SELECTION 的特征需求 |
| **已完成步骤** | INIT → ANALYSIS → MODEL_SELECTION |
| **缺失信息** | 某些参数值需要从数据中估计 |
| **下一动作** | 进入 SOLVING |
| **状态保持数据** | `{X(numpy), y(numpy), feature_names, data_quality_report}` |

**调用**: `data_processing/workflow.md` (6步管道)

**可跳过条件**: 如果模型不需要数据（如纯优化问题），直接跳到 SOLVING

---

### S4: SOLVING — 模型求解

| 维度 | 内容 |
|------|------|
| **当前任务** | 运行求解器，获取数值结果 |
| **输入** | MODEL_SELECTION 的模型+ DATA_PROCESSING 的清洁数据 |
| **已完成步骤** | ... → MODEL_SELECTION → [DATA_PROCESSING] |
| **缺失信息** | — |
| **下一动作** | 进入 VALIDATION |
| **状态保持数据** | `{solution_values, solver_status, iterations, experiment_log}` |

**调用**: `模型求解流程.md` + `numerical_computing/`

---

### S5: VALIDATION — 结果验证

| 维度 | 内容 |
|------|------|
| **当前任务** | 用统计指标和物理意义验证结果 |
| **输入** | SOLVING 的结果 + 原始数据 |
| **已完成步骤** | ... → SOLVING |
| **缺失信息** | — |
| **下一动作** | 通过 → PAPER_GENERATION；不通过 → FAILOVER |
| **状态保持数据** | `{validation_metrics, sensitivity_results, stability_check}` |

**验证维度**（参考 `模型验证方法.md`）:
- 准确性: 测试集误差 / 拟合优度 R² / 预测准确率
- 稳定性: 交叉验证 / 参数扰动 ±10% / 多次运行统计
- 可解释性: 变量重要性 / 方向合理性
- 物理可行性: 结果是否在物理/经济意义上合理

**Checkpoint**: ⚑ 人工确认点 — 结果是否符合预期？是否可信？

---

### S6: PAPER_GENERATION — 论文生成

| 维度 | 内容 |
|------|------|
| **当前任务** | 汇总所有结果，生成论文 |
| **输入** | 所有前序状态的输出 |
| **已完成步骤** | 全部建模步骤 |
| **缺失信息** | — |
| **下一动作** | DONE |
| **状态保持数据** | `{paper_docx_path, figures, tables}` |

**调用**: `math-modeling-paper` Skill

---

### S7: DONE — 完成

所有任务完成，进入 Project Closure Workflow（参考 `standards/project_closure.md`）。

## 三、Failover 异常处理机制

> 参考 LangGraph 的 Checkpoint + 条件路由：在关键节点设置回退路径。

### 异常 1: 数据不足

```
触发条件: S3 DATA_PROCESSING 发现关键数据缺失 > 30% 或样本量 < 阈值
动作: 回退到 S1 ANALYSIS
      重新分析哪些信息可以从其他来源补充
      或者调整模型选择（降级到对数据要求更低的模型）
示例: ARIMA 需要 >30 个数据点 → 只有 20 个 → 降级为 GM(1,1)
```

### 异常 2: 模型无法求解

```
触发条件: S4 SOLVING 求解器返回 success=false
动作: 回退到 S2 MODEL_SELECTION
      使用 failover_model（备选方案）
      或者换求解方法参数
示例: linprog 返回 infeasible → 检查约束是否矛盾 → 放松约束 → 或换 milp
```

### 异常 3: 验证失败

```
触发条件: S5 VALIDATION 指标不达标 (R²<0.4 / 准确率<基线)
动作: 回退到 S2 MODEL_SELECTION
      重新审视模型假设是否合理
      考虑是否漏掉了重要特征
      或切换到完全不同类型的模型
示例: 线性拟合 R²=0.3 → 检查散点图 → 发现是非线性关系 → 换非线性拟合
```

### 异常 4: 结果不可解释

```
触发条件: 结果数值与常识/物理定律矛盾
动作: 不立即回退
      先检查数据是否正确（回到 S3）
      再检查求解是否正确（回到 S4）
      最后考虑是否需要增加解释性分析模型
示例: 预测人口出现负增长 → 检查数据单位 → 发现"万人"与"人"混淆
```

### Failover 决策表

| 异常 | 检测点 | 回退到 | 降级路径 |
|------|--------|--------|----------|
| 数据不足 | S3 | S1 或 S2 | 高要求模型 → 低要求模型 |
| 求解失败 | S4 | S2 | 首选方法 → 备选方法 |
| 验证不通过 | S5 | S2 或 S3 | 当前模型 → 更简单模型 |
| 结果不合理 | S5 | S3 或 S4 | 增加数据检查步骤 |

## 四、状态流转测试案例

### 测试 1: 销量预测

```
INIT: 读入 10 年销售数据 (CSV)
  ↓
ANALYSIS: 识别为"预测"问题, 数据含时间维度, 有12个数据点
  ↓
MODEL_SELECTION: 数据点<30 → 选择 GM(1,1) 灰色预测
  ↓
DATA_PROCESSING: 检查缺失值, 按年份排序, 提取目标列
  ↓
SOLVING: 累加生成 → 最小二乘 → 还原预测值
  ↓
VALIDATION: 后验差比 C=0.28 < 0.35 ✓, 残差正态 ✓
  ↓
PAPER_GENERATION: 生成预测图表 + 论文
  ↓
DONE
```

### 测试 2: 工厂生产优化

```
INIT: 读入问题描述（无附件数据）
  ↓
ANALYSIS: 识别为"优化"问题, 线性目标+线性约束
  ↓
MODEL_SELECTION: 线性规划, sub_type=资源分配
  ↓
DATA_PROCESSING: (跳过, 数据嵌入在问题描述中)
  ↓
SOLVING: scipy.optimize.linprog → x=[22,14], profit=9400
  ↓
VALIDATION: 约束100%满足, KKT条件✓, 敏感性分析稳定
  ↓
PAPER_GENERATION
  ↓
DONE
```

### 测试 3: 城市综合评价

```
INIT: 读入 20城市×6指标 数据
  ↓
ANALYSIS: 识别为"评价"问题, 需要多维度排名
  ↓
MODEL_SELECTION: 熵权法 + TOPSIS
  ↓
DATA_PROCESSING: 缺失填充(中位数), 异常截断(IQR), Z-score标准化
  ↓
SOLVING: 熵权法计算权重 → TOPSIS 计算贴近度 → 排序
  ↓
VALIDATION: 权重总和=1 ✓, 排名与常识一致 ✓
  ↓
PAPER_GENERATION
  ↓
DONE
```
