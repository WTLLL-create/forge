## D-2：欠拟合（Underfitting）

### 症状

```
训练集: R² = 0.45（或 Accuracy = 68%）
测试集: R² = 0.43（或 Accuracy = 66%）
差距: < 0.05 → 训练和测试都差 → 不是过拟合，是欠拟合
```

学习曲线：训练和验证误差都高，且两者接近——模型根本没学到东西。

### 根因诊断

| 根因 | 诊断方法 | 验证 |
|------|----------|------|
| 模型太简单 | 换一个稍复杂的模型，性能是否提升？ | 线性→RF→XGBoost，看R²趋势 |
| 特征不足 | 增加特征后是否提升？ | 比较：原始特征 vs 原始+新特征 |
| 假设过强 | 模型假设与数据特征是否冲突？ | 线性模型 → 检查残差-拟合值图 |
| 数据噪声过大 | 信噪比低 | σ_noise/σ_signal > 0.5 |

### 修复

```
数据噪声大 → 先验知识注入 / 鲁棒损失函数
模型太简单 → 增加模型复杂度 / 换更强模型
特征不足 → 构造更多有物理意义的特征
假设过强 → 放松假设（线性→非线性，同方差→异方差）
```

## D-4：泛化能力不足（Poor Generalization）

### 症状

训练集和测试集（同分布）表现尚可，但换一个数据集/场景后性能大幅下降。

### 根因诊断

| 根因 | 诊断方法 |
|------|----------|
| 训练数据不代表真实部署场景 | 比较训练集和真实场景的数据分布 |
| 模型过拟合了训练数据分布的特异点 | 在不同子集上评估稳定性 |
| 数据划分时的分布漂移未处理 | 检查训练/测试的特征分布差异 |

### 修复

```
分布差异 → 对抗验证 / Domain Adaptation
时序漂移 → 滚动窗口训练
样本偏差 → 分层采样 / 加权
```

## D-5：模型不稳定（Instability）

### 症状

```
Run 1: R² = 0.82
Run 2: R² = 0.54
Run 3: R² = 0.71
标准差 > 0.1 → 模型不稳定
```

### 根因诊断

| 根因 | 诊断方法 |
|------|----------|
| 样本量太小 | N < 200 → 每次bootstrap/初始化产生完全不同的模型 |
| 高方差算法 | RF（bootstrap自带随机性）; K-means（初始点随机） |
| 随机种子未固定 | 不同run使用了不同seed → 无法复现 |
| 数据包含异常值 | 异常值在不同fold中出现→影响差异大 |

### 修复

```
固定随机种子：np.random.seed(42)
多次运行取平均：至少5次，报告均值±标准差
增大集成规模：RF增加n_estimators（≥300）
增大样本量：如果可能
使用更稳定的算法：XGBoost > RF（boosting比bagging更稳定）
```

### 论文表达

```
为验证模型的稳定性，本文进行了5次独立运行。
结果（表X）显示：[指标]的均值为[X]±[std]，
变异系数仅[CV]%，表明模型对随机种子和初始条件不敏感。
```

## D-6：可解释性不足（Interpretability Failure）

### 症状

模型效果很好，但论文无法解释"为什么"——这对于竞赛论文是致命的。

### 根因

选择了黑箱模型（LSTM/深度学习）但没有配套的解释工具。

### 修复（按可解释性递增排序）

| 方案 | 可解释性 | 精度损失 | 做法 |
|------|:---:|:---:|------|
| 特征重要性（RF内置） | ★★ | 无 | feature_importances_ |
| 排列重要性 | ★★ | 无 | 打乱每列看精度下降 |
| SHAP值 | ★★★ | 无 | shap.TreeExplainer / shap.KernelExplainer |
| 偏依赖图(PDP) | ★★★ | 无 | 保持其他变量不变，看一个变量的效应 |
| GAM（广义加性模型） | ★★★★ | 有 | 每个特征独立的平滑函数，可视化 |
| 线性模型+标准化系数 | ★★★★★ | 有 | 系数=影响力，符号=方向 |

### 论文表达

```
虽然RF的预测精度优异（R²=0.85），但其黑箱特性
无法直接揭示各因素的影响机制。
为此，本文使用SHAP方法对RF的预测进行归因分析。

SHAP分析（图X）表明：
[特征A]贡献了[X%]的预测方差，影响方向为[正/负]；
[特征B]在[条件]下影响显著，但在[条件]下几乎无影响。
这与[领域知识]一致，验证了模型的合理性。
```

## D-7：结果可信度不足（Evidence Failure）

### 症状

模型给出了结果，但没有任何手段证明这个结果可信。

### 典型表现

```
"最优方案：x₁=2.3, x₂=5.7, 最大利润=9400"

但没说：
- 这个最优是不是全局最优还是局部最优？
- 参数变化±10%时结果变化多大？
- 换一个近似模型结果是否一致？
- 置信区间是多少？
```

### 修复对照

| 缺失的证据 | 补充方法 | 论文表达 |
|-----------|----------|----------|
| 全局最优性 | 多起点/不同的初始值→结果一致 | "从[N]个随机起点收敛到同一解，表明是全局最优" |
| 敏感性 | ±10%扰动 | "参数±10%变化时，目标变化<5%，方案鲁棒" |
| 方法一致性 | 换一个近似方法重算 | "LP松弛解与启发式解差距<3%，验证了近似质量" |
| 置信区间 | Bootstrap CI | "最优利润的95% CI为[9150, 9650]" |
| 基线对比 | 与简单策略对比 | "相比均匀分配方案，本文方案提升23%" |

### 核心原则

```
每一条"最优""最好""有效"的声明，后面必须跟一个定量的证据。
没有证据的声明 = 不可信的声明。
```
