# D-1：过拟合（Overfitting）

> 最常见、最容易被忽视的建模失败模式。
> 训练集上看起来完美，测试集上一塌糊涂。

---

## 一、症状

### 典型表现

```
训练集: R² = 0.98（或 Accuracy = 99%）
测试集: R² = 0.35（或 Accuracy = 55%）
差距:   > 0.5 → 严重过拟合
        > 0.2 → 中度过拟合
        > 0.1 → 轻度过拟合
```

### 可视化信号

```
学习曲线：
  训练误差 → 持续下降
  验证误差 → 先下降，然后上升（U型）
  → 两条曲线的"分叉点"就是过拟合开始的位置

决策边界（分类）：过度曲折、有孤岛
预测值分布：被"压缩"在训练集范围内
```

### 其他信号

- 模型使用了大量参数但数据量不大（参数数 > N/10）
- 树模型设置了 max_depth=None（无限生长）
- 没有使用任何正则化
- 在时序数据上使用了随机交叉验证（而非时间切分）

---

## 二、根因诊断

### 根因 1：模型复杂度过高（最常见）

```
诊断方法：
  计算有效参数数 / 样本量
  如果 > 0.1 → 模型太复杂

  例如：
  RF: n_estimators=500, max_depth=None, N=200
  → 每棵树可长到 ~log₂(200)≈8 层，500棵树 × ~256 叶节点
  → 有效参数数远超 N

验证方法：
  降低 max_depth 从 None → 3 → 5 → 7
  看测试集R²是否先升后降
  → 如果降低复杂度后测试R²反而提升 → 确认过拟合
```

### 根因 2：特征数量过多

```
诊断方法：
  特征数 p  vs  样本量 N
  p > N/3 → 高维风险
  p > N → 必然过拟合（参数数 > 方程数）

验证方法：
  逐步减少特征数（从最重要的开始保留）
  看测试R²趋势
```

### 根因 3：数据划分错误（伪过拟合）

```
诊断方法：
  时序数据是否用了随机k-fold？
  → 如果是 → 训练集中混入了未来的信息 → 伪过拟合
  → 正确做法：时间切分（训练=过去，测试=未来）

  分类数据是否分层抽样？
  → 如果是 → 但类别极度不平衡且在验证集做特征选择 → 伪过拟合
```

### 根因 4：数据泄漏（见 D-3）

过拟合可能是数据泄漏的表现。详见 `data_leakage.md`。

---

## 三、修复策略

| 修复 | 做法 | 预期效果 |
|------|------|:---:|
| **降低模型复杂度** | RF: max_depth=5~15, min_samples_leaf=5~20 | 训练-测试差距缩小 |
| | LSTM: 减少层数/隐藏单元，增加dropout | |
| | XGBoost: max_depth=3~6, reg_lambda>0 | |
| **正则化** | L1(Lasso)/L2(Ridge)/ElasticNet | 约束参数大小 |
| | Dropout（NN）: 0.2-0.5 | 随机丢弃神经元 |
| | Early Stopping: 验证误差不再下降即停 | 防止过度训练 |
| **交叉验证** | k-fold（非时序数据） | 获得泛化误差的无偏估计 |
| | 时间序列交叉验证（时序数据） | |
| **数据增强** | 合成少数类样本（SMOTE） | 增加有效样本量 |
| **特征筛选** | 基于相关性/重要性/VIF筛选 | 减少噪声特征 |

### 修复优先级

```
1. 先降低模型复杂度（最快、最有效）
2. 加入正则化
3. 增加交叉验证
4. 特征筛选
5. 数据增强（最后手段，因为可能引入偏差）
```

---

## 四、修复后的验证

```
修复后必须验证：
□ 训练-测试差距是否缩小到 < 0.15？
□ 学习曲线是否不再出现 U 型反弹？
□ 测试集R²是否提升？
  （如果降低复杂度后测试R²反而提升了→说明之前确实过拟合了）
□ 是否在独立的留出集（holdout）上验证？
```

---

## 五、论文表达

```
❌ 不解释：
  "本文使用随机森林模型，max_depth=5。"

✅ 有诊断的论文表达：
  "在使用默认参数（max_depth=None）时，发现训练集R²=0.98
  但测试集R²仅0.35——差距达0.63，表明严重过拟合。
  通过逐步降低树的深度（图X）发现：当max_depth从None降至5时，
  测试集R²升至0.71，而训练集R²仅降至0.85——差距缩小至可接受的0.14。
  这一调整平衡了模型的表达力与泛化能力。"
```

## 六、与已有系统的对接

```
触发条件：
  train_test_gap > 0.2

ErrorLifecycle 分类：Type B (参数问题)
  回退策略：S4 (求解) → 降低复杂度 + 正则化 → 重新求解

QualityGateway 检查：
  overfit_check: train_test_gap < 0.15？

FailurePattern 记录：
  symptom: "训练R²=0.98, 测试R²=0.35, 差距=0.63"
  root_cause: "RF max_depth=None → 模型复杂度过高 → 过拟合"
  remediation: "max_depth=None→5, 测试R²从0.35→0.71"
```
