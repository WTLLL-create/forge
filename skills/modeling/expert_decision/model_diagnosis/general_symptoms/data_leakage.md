# D-3：数据泄漏（Data Leakage）

> 数学建模竞赛中最隐蔽、最常见的严重错误。
> 泄漏发生时模型表现异常好，但论文提交后评委会发现：你的结果不可能那么好。

---

## 一、症状

### 典型表现

```
Accuracy = 99.7%（或 R² = 0.999）
RMSE 接近零
预测值和真实值几乎重叠

→ 这不是模型好，是信息泄漏了。
```

### 为什么泄漏比过拟合更危险

```
过拟合：训练好，测试差 → 容易发现
数据泄漏：训练好，测试也好（因为测试集也被污染了）→ 很难发现
```

---

## 二、六种常见泄漏模式

### 泄漏模式 1：在划分训练/测试集之前做了全局预处理

```
❌ 错误做法：
  scaler = StandardScaler()
  X_scaled = scaler.fit_transform(X_all)  # 在整个数据上fit！
  X_train, X_test = split(X_scaled)       # 然后才划分
  → scaler.fit() 看到了测试集的数据！
  → 测试集的均值和标准差信息泄漏到了训练集

✅ 正确做法：
  X_train, X_test = split(X_raw)
  scaler = StandardScaler()
  X_train_scaled = scaler.fit_transform(X_train)  # 只在训练集上fit
  X_test_scaled = scaler.transform(X_test)         # 对测试集只transform
```

### 泄漏模式 2：在时序数据上使用随机划分

```
❌ 错误做法：
  将时间序列数据随机打乱，然后80/20划分
  → 训练集中有"未来"的数据
  → 模型学会了"看到未来"→ 但现实中做不到

✅ 正确做法：
  训练集 = 前80%的时间点
  测试集 = 后20%的时间点
  验证集 = 训练集的后20%（同样按时间切分）
```

### 泄漏模式 3：在划分前做了特征选择

```
❌ 错误做法：
  feature_importance = RF.fit(X_all, y_all)  # 在整个数据上选特征
  X_selected = X_all[:, top_k_features]
  X_train, X_test = split(X_selected)

✅ 正确做法：
  X_train, X_test = split(X_raw)
  feature_importance = RF.fit(X_train, y_train)  # 只在训练集上选
  X_train_selected = X_train[:, top_k]
  X_test_selected = X_test[:, top_k]
```

### 泄漏模式 4：使用未来信息构造特征

```
❌ 错误做法（时序预测）：
  df['rolling_mean_7d'] = df['target'].rolling(7).mean()
  → rolling(7)默认包含当前值 → 特征中包含目标信息！
  
  df['next_day_value'] = df['target'].shift(-1)
  → 把明天的目标当成了今天的特征！

✅ 正确做法：
  df['rolling_mean_7d'] = df['target'].shift(1).rolling(7).mean()
  → 用过去7天（不含今天）的值
```

### 泄漏模式 5：在训练集上进行超参数搜索的交叉验证中泄漏

```
❌ 错误做法：
  用全数据进行GridSearchCV → 选最优参数 → 在同一个全数据集上评估
  → 超参数选择过程中看到了所有数据

✅ 正确做法：
  X_train, X_test = split(X)
  GridSearchCV.fit(X_train)  → 选最优参数
  在 X_test 上评估（X_test 从未参与参数选择）
```

### 泄漏模式 6：重复记录/ID泄漏

```
❌ 错误做法：
  数据中有重复记录，随机划分时同一人的两次记录分别进入训练和测试集
  → 模型记住了这个人而非学会了一般规律

✅ 正确做法：
  按ID分组划分，确保同一ID的所有记录在同一集合中
```

## 三、泄漏检测方法

| 检测方法 | 做法 | 判据 |
|----------|------|------|
| 时序泄漏 | 随机打乱数据后性能是否明显下降？ | 若下降>20% → 确认时序泄漏 |
| 预处理泄漏 | 重新运行整个pipeline，严格先划分再预处理 | 性能是否显著下降？ |
| 目标泄漏 | 逐一检查每个特征与目标的时序关系 | 是否有特征使用了目标的未来值？ |
| Holdout验证 | 保留一个完全不参与任何处理的留出集 | Holdout vs 测试集差异>10% → 有泄漏 |

---

## 四、修复

数据泄漏没有"修复"——泄漏意味着整个实验无效。必须：

```
1. 定位泄漏点
2. 修复数据划分/预处理/特征工程的顺序
3. 从零重新运行整个实验
4. 保留Holdout集做最终验证
```

---

## 五、论文表达

```
❌ 不要报告泄漏后的结果
  "本文模型Accuracy达到99.7%"
  → 如果评委发现是泄漏 → 直接重扣或退回

✅ 如果发现了数据划分问题并修正：
  "在初步实验中，随机划分给出了异常高的准确率（99.7%）。
   经诊断发现，这源于时序数据中训练集包含了未来信息。
   修正为时间切分后准确率降至合理的82%——
   后者反映了模型在真实预测场景下的表现。"
   → 诊断本身变成了论文中的诚实加分项
```

## 六、竞赛中的典型泄漏案例

### 案例：2021B 空气质量预测

```
泄漏方式：
  构造了"未来24小时平均PM2.5"作为特征
  → 但未来值在预测时是未知的
  → 模型达到了异常高的R²=0.97

发现方式：
  在纸上推演：如果模型在t时刻预测t+1到t+24的PM2.5，
  那么"未来24小时均值"在t时刻确实未知
  → 逻辑检查而非统计检查
```

### 自检规则

```
每构造一个新特征时，问自己：
  "在预测的时刻，这个特征的值是已知的吗？"
  如果答案是"否" → 泄漏
```
