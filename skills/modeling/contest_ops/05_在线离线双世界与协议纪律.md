# 05 在线/离线双世界与协议纪律

> 适用：带官方模拟器/在线接口的赛题（控制器在只可见当前观测的条件下串行决策，正式测试机会有限）。
> 解决的问题：控制器偷看真值、离线模拟器与官方行为不一致、把演练/离线成绩当正式成绩、浪费仅有的正式机会。

---

## 1. 两个世界物理隔离

| | 离线世界（自建裁判器） | 在线世界（官方模拟器） |
|---|---|---|
| 真值 | 可生成并持有源位置/半径/朝向，用于裁判 | 真实布局不可读，控制器只能用合法接口信息 |
| 控制器访问 | **绝不允许**控制器访问真值 | 仅依靠 `/enter /measure /clear /exit` 的合法响应 |
| 日志标记 | 文件名/内容显著标 `OFFLINE` | 保留官方原始文件名，不改不造 |
| 时间 | 自己记账，必须另用"官方独立时钟"对账 | 以响应里的 `virtual_time_s` / 时间戳为唯一权威 |
| 用途 | 大样本回归、压力、故障注入、消融 | 演练（不限次）+ 正式测试（每题仅 3 次） |

铁律：

1. 两个世界的日志、摘要、字段来源明确隔离；不得把离线成绩写成官方成绩。
2. 离线裁判器可以用真值做断言和"同布局对照"，但真值与控制器输入分开存放。
3. 正式成绩表、案例编码、加密日志只能来自真实响应；**没有成功 exit 时间戳就标缺失**，
   不能用本机秒表冒充官方时长；成功数为 0 时均值留空/未定义。
4. 缺失的正式结果一律留空，绝不虚构；官方加密 jlog 不解密、不改名、不补造。

## 2. 在线协议纪律（以 2026 B 为例，通用化）

1. **严格串行**：等上一响应完整返回再发下一动作；同时检查 HTTP 状态与 `accepted`；
   `accepted=false` 不更新位置/频道/最近虚拟时刻。
2. **幂等**：每个新动作新 `request_id`；同一动作的传输重试必须**完整复用原 payload 与 ID**，
   不能因超时就生成新 ID 重复清除。
3. **计时口径**：以官方公式独立记账（移动/速度 + 检测 + 切频道 + 成功/失败清除）；
   注意"`/clear` 不切换测向频道"这类易实现错的规则；不能为虚拟 5 秒在现实里 sleep 5 秒。
4. **截止门控**：用 `/enter` 返回的 `remaining_real_duration_s` 与虚拟上限（如 360000）双重门控；
   读取了剩余时长却不据此建立门控属于缺陷。
5. **只使用官方字符串**：direction/near/no_signal/success/no_target_in_range/user_exit 等，不自造状态。
6. **网络加固**：
   - "不确定是否执行"的错误（超时/连接重置/无响应）复用原请求原 ID，做带抖动的指数退避，总等待受剩余现实时间约束；
   - 400/404/405/409/413/415 属程序错误不盲重试；429/500 有上限退避；`accepted=false` 记录原因；
   - 进入前连接失败与进入后传输失败分开处理；
   - 每个已接受动作立即增量落盘（请求/响应/ID/版本/最近已接受虚拟时刻/状态快照），异常退出可重建现场；
   - `/exit` 用独立重试预算，模拟器关闭后不反复查询；永久故障只能安全失败并如实报告，不可能保证成功。
7. **正式测试机会纪律**：演练不限次、正式测试每题 3 次且手工中止也消耗机会；
   **AI 不得自动启动正式测试**，由人确认后人工执行；不在倒计时窗口外做无谓尝试。

## 3. 离线验证设计

### 3.1 先离线后演练，再正式
新版本先独立离线验证（一键运行、固定种子），再由人启动官方演练，最后才是正式测试。
离线模拟器必须为新问题**独立实现**，不能把上一问题的模拟器改个名字顶替
（实战：全向的 simulate_q3 不能当含定向源的 Q4 验证器）。

### 3.2 样本与分层
- 每档（N=10..16）至少 200 组独立留出布局；重点档（最难的 N=10/11）建议 1000 组；
- 训练/测试种子分离，给出生成分布；
- 场景覆盖：随机混合、贴边、全定向外向、半定向外向、聚集/分散/共线/近邻/最差布局、
  R=1000/R=1500/混合、±1° 与两位小数量化边界、最小 1000m 半径、圆域边缘；
- 同地点同频道误差固定（模拟"同地电磁环境固定"）；不同策略对比用**同布局 + 确定误差场**。

### 3.3 必须报告的统计量
全部清除率、异常局、未清频道、误判无源、mean/median/P90/P95/worst、均值置信区间；
每源测量次数与路程（定位专属 vs 全局分摊）、最大真实清除距离、扑空次数、兜底比例/耗时、补扫耗时；
分层报告，不合并稀释；给可复现种子与失败样例，**不删除失败后重算**。

### 3.4 故障注入
响应丢失、超时、HTTP 400/409/413/415/429/500、`accepted=false`、冲突 ID、重复响应、永久网络失败、时间到期。
- 暂态故障：断言"失败一次、恢复成功"，同一动作只执行一次；
- 永久故障/时间不足：明确报告未完成，**不计入成功局**；
- 正常物理场景仍断言扑空 0、全清；故障场景断言安全失败，二者不能混为一谈。

### 3.5 终止与资源界
每个循环/递归（含内部路径改进循环）给硬上限或严格终止证明；
覆盖任务不被饿死，也不退化为"先扫完再逐源"；
证明理想合法接口下完成任务的资源界；网络永久故障时诚实说明只能安全失败。

## 4. 控制器代码纪律（实战固化）

- 正式控制器只用允许的库（实战要求仅标准库 + `urllib.request`，HTTP 严格串行）。
- 常量（队号、BASE_URL、ARENA_ID）由部署确认；**真实队号不得写进公开代码/报告**，启动脚本不要硬编码。
- 只新建自己的版本文件（如 `solve_q3_280.py`、`solve_q4.py`），**禁止覆盖任何已有 `.py` 或官方文件**，
  不得把旧版本改名当新版；历史版本保留作基线。
- 离线研究脚本若用了第三方库，要明确标注环境，不能据此推断正式控制器也依赖第三方。
- 运行第三方目录时禁止外部字节码写入（避免在旧目录生成 `__pycache__` 污染原件），用内存编译或禁写缓存。

## 5. 成绩自证与表1纪律

- 每局记录：案例编码、成功清除数、`virtual_time_s/成功清除数`、现实耗时（用 exit 与 enter 的时间戳差）。
- 演练验收：异常未清列表为空；成功数 = 结束弹窗总 N；判无源数 = 频道数 − N；
  重复成功频道不重复计数；已清与无源互斥并覆盖全部频道。
- 正式测试不显示真 N，局内完备性靠**算法证书**，不能只依赖自报成功数；
  不能用清除计数反推总 N，不能用 P95 成功代替必然清除。
- 单局门槛达标率按"每局 `T/cleared ≤ 阈值`"逐局判定，再统计比例；不得用合并均值宣布"每局都达标"。

## 6. 与其他手册的接口

- 双世界产出的每个数字都要进事实表并标证据等级（[02](02_证据边界与事实表.md)）。
- 不变量与故障注入是对抗复核（[03](03_对抗性逻辑碰撞复核.md)）的 D 组内容。
- 离线模拟器的时钟/协议偏差是阶段0审计（[04](04_阶段0现状审计与下界纪律.md)）的必查项。
- 交接包（[01](01_跨模型交接包协议.md)）必须包含本文件的接口与验收说明，且明确"不得自动启动正式测试"。
