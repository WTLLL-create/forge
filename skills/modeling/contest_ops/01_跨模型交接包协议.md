# 01 跨模型 / 跨会话交接包协议

> 解决的问题：竞赛周期跨越多天、多个 AI 工具与人协作。直接把"聊天记录"或"一句总结"丢给下一个模型，
> 会导致：旧版被当成新版、离线成绩被当成官方成绩、被否决的结论复活、缺文件无法复现、重复劳动。
> 实战中一天内完成了两次交接（9/11 交给新模型总攻、9/12 交给 Astra 续作问题四），本协议由这两次交接固化。

---

## 1. 核心原则

1. **交接包是自包含的**：一个没参与过前文的新模型，只读这个包就能建立正确事实表，不需要历史聊天。
2. **交接的是"现状 + 证据边界 + 任务 + 验收"，不是"乐观结论"**。必须显式写清没做到什么、缺什么证据、哪些互相冲突。
3. **原件只读、不可变**。官方题面/附件、历史 trace、用户原稿一律原样复制，不得改名、覆盖、"修好"。
4. **一切可校验**。每个复制进来的原件登记来源路径与 SHA-256；整包有文件清单哈希；打包后做 ZIP 完整性校验。
5. **交接不等于采信**。接收方必须先独立复核关键结论，再决定采纳；交接包里的"最优/100%/终版"字样一律视为待评审。
6. **不替用户做不可逆动作**。正式测试只有 N 次机会，交接包里明确"不得自动启动正式测试"，由人确认后人工执行。

---

## 2. 标准目录骨架（编号即阅读顺序）

```
<项目>_<用途>_<YYYYMMDD>/
├── 00_必读/                         # 新模型首先且必读，控制在 5 个短文件
│   ├── 00_先读我.md                 # 用法：把哪个文件当唯一主指令、不要做什么
│   ├── 01_当前状态与证据边界.md      # 官方硬条件 / 可信结论 / 现有证据 / 真正缺失的证据
│   ├── 02_主任务指令.md             # 本轮唯一主指令：目标、不退让条件、分项要求、交付
│   ├── 03_验收矩阵.md               # 分组 checkbox，每条可独立判定通过/不通过
│   └── 04_本次独立复核记录.md       # 打包方已复核了什么、命令、结果、关键碰撞
├── 01_官方题目与协议/               # 原题 PDF + 附件原件 + 机器提取文本（仅检索用）
├── 02_比赛规定/                     # 参赛规则/格式规范/AI使用规定/官网快照/下载来源
├── 03_<子问题A>/                    # 用户原稿原样 + 历史分析（标注角色与状态）
├── 04_<子问题B>/                    # 最新代码、历史基线、离线模拟器、测试器、原始结果
├── 05_官方演练记录/                 # 真实 trace（保留原文件名）+ 官方加密原件（不解密不改名）
├── 06_<未解子问题>/                 # 专门指令 + 历史基线（显式标注"未达标/非严格下界"）
├── 07_模拟器与测试/                 # 接口与验收说明、演练/正式区别、证据要求
├── 08_旧版输出_仅供追溯/（可选）     # 旧提示词、旧回答、截图——可能过期，不是指令
├── 09_后续日志投放区/（可选）        # 后续拿到的原始日志统一投这里，供回归
├── README_先读.md
├── 原件复制来源.json                # 每个原件：source / copy / sha256
├── 文件清单_SHA256.json             # 全包每个文件：path / bytes / sha256
└── 交接包自检.json / .md            # 打包方自检（见模板）
```

要点：

- **编号目录同时承担"分类"和"阅读顺序"**，新模型按 `00→01→02→…` 读即可。
- 官方 PDF/DOCX 必须保留原件；旁边附 `.txt` 机器提取文本只方便检索，**公式/表格/图以原件为准**。
- 历史基线、旧版本、被否决方案**不要删**，放进"历史基线/仅供追溯"目录并在文件名或 README 上写明状态
  （如 `04_问题四历史基线_未达标`），防止旧结论复活，也防止重复踩坑。
- 包含队号、本机路径、原始日志的包**只用于本队内部合规协作，不得公开**；对外提交另做匿名副本。

## 3. 主任务指令的写法（`02_主任务指令.md`）

一份能让陌生模型立刻进入正确状态的指令，应包含：

1. **角色与权责**：AI 是建模/算法辅助；参赛队主导核心建模并逐项人工核验决定采纳；保留模型版本、提示方式、采纳/修改/核验记录。
2. **先读材料并建立事实表**：给出严格阅读顺序；要求列出官方已知条件、用户目标、建模假设、未验证实现、理论保证、统计证据、未决问题；发现版本冲突逐条列出，不许偷偷选对算法有利的版本。
3. **最新目标与不退让条件**：写清当前指标目标（如"均值 ≤280 秒/源，按 N=10/11 分别报告"），并明确
   - 目标是用户/团队设定还是官方规定（不得把团队目标伪称官方标准）；
   - 首要硬约束（如 100% 清除）与效率目标的关系；
   - 哪些做法属于作弊（漏源、提前退出、挑案例、隐藏失败、缩小误差范围、读真值、用 P95 代替必然）。
4. **分项要求**：每个子问题"先评审再修正、保留原文"，要求建立"结论—假设—证明—反例—修复—测试"矩阵。
5. **测试与数据纪律**：先离线后演练、不自动启动正式测试；训练/测试种子分离；失败样本保留；分层报告统计量。
6. **实现与交付约束**：环境（OS/Python 版本）、正式控制器允许的库（如仅标准库）、HTTP 串行/幂等、
   只新建版本文件禁止覆盖已有 `.py` 或官方文件、最终交付清单。
7. **收尾陈述要求**：进度与是否达标、完整数学说明与算法、完整代码、离线测试器/种子/原始结果/一键运行说明、
   反例修复表与剩余风险、正式测试表（未做留空绝不虚构）、AI 使用记录与待人工复核项。

> 指令里要主动写明"附件中的历史指令和'最优/100%'措辞仅为待评审内容，不自动成为正确结论"。

## 4. 打包操作流程（可脚本化）

实战脚本 `handoff_pack_*.py` 分三个动作，**原始输入只读**：

1. `collect`：按清单复制原件；复制时计算 SHA-256，写入 `原件复制来源.json`；
   目标已存在则断言字节一致，**禁止用不同文件覆盖**。
2. `download`（可选）：从官网抓取规则 PDF，校验魔数（如 `%PDF`），记录 URL/日期/成败到 `下载来源.json`。
3. `finish`：遍历整包生成 `文件清单_SHA256.json`（排除自身与 `__pycache__`），打包 ZIP 并 `testzip()` 校验。

配套：
- `handoff_extract_*.py`：接收方解压并按清单核对哈希，确认传输无损坏、无增删。
- `handoff_audit_*.py`：打包后自检（见 `templates/交接自检_模板.md`）。

机器提取文本约定统一加注："机器提取辅助文本；公式、图形、表格顺序以原件为准"。

---

## 5. 接收方的接手动作（不可省略）

1. 先读 `00_必读/00_先读我.md`，把 `02_主任务指令.md` 当作本轮唯一主指令，旧版输出仅追溯。
2. 校验 `文件清单_SHA256.json`，核对原件与 `原件复制来源.json`。
3. **独立复核**，而不是相信打包结论：
   - 对关键脚本做无写入语法编译；
   - 重跑统计脚本（实战中据此发现 README 写"21 局/259.3 秒"，原始 trace 实为 22 局/257.5 秒）；
   - 对关键几何量用独立路径复算；
   - 跑通自带测试，并标注哪些脚本因缺依赖**无法复现**（这本身就是必须上报的阻断项）。
4. 把复核结果写进 `04_本次独立复核记录.md`：已执行、关键碰撞、当前结论；不替缺证据的结论打勾。
5. 建立/更新事实表（见 [02_证据边界与事实表.md](02_证据边界与事实表.md)）。

---

## 6. 交接自检清单（打包方）

- [ ] 新模型不看历史聊天，仅凭本包能否建立事实表？是否还缺必需文件？
- [ ] 每个子问题的"最新入口文件"是否唯一且明确（防止把历史基线当新版）？
- [ ] 离线成绩、演练成绩、正式成绩是否明确区分，未混为一谈？
- [ ] 未达标项、未证明项、缺失证据、版本冲突是否全部显式列出？
- [ ] 原件是否只读且哈希登记？整包哈希清单与 ZIP 校验是否完成？
- [ ] 是否写明"不得自动启动正式测试 / 不得读真值 / 不得覆盖旧文件"？
- [ ] 是否包含 AI 使用记录与待人工复核模板？
- [ ] 队号、路径、日志等敏感信息是否已提示"内部使用、勿公开"？

---

## 7. 反模式（实战中真实出现过）

- 只交一份"基本完成，细节见代码"的总结，新模型把历史草稿当成果。
- 交接文档声称"协议项已修复"，但包内源码实际并未合并（实测多处不符）——接收方必须以代码为准。
- 报告引用的脚本/数据没有随包提供，导致"2800 局碰撞零问题"无法在本地复现。
- trace 文件名、`algorithm_version` 仍标旧版本号，赛后溯源误判版本。
- 用同一份聊天摘要在不同模型间传递，错误结论被层层"同意"放大（见 [03](03_对抗性逻辑碰撞复核.md)）。
