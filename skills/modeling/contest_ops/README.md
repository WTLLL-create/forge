# contest_ops — 竞赛实战操作层

> 定位：数学建模技能体系中"人 + 多个 AI 工具 + 官方模拟器/在线系统"协同作战时的**操作层**。
> 它不替代 `数学建模完整流程.md`（教学型 10 阶段）与 `core/runtime/`（v8/v9 证据链生产运行时），
> 而是补上它们没有覆盖的部分：**跨会话/跨模型交接、证据边界管理、对抗性自证、卡住时的阶段0审计、
> 在线/离线双世界纪律、可复现论文图集**。
>
> 成熟度：**beta（单项目实证）**。本层全部方法来自 2026 年全国大学生数学建模竞赛 B 题
> （无线电干扰源快速自动定位与清除，在线模拟器型赛题）的一次完整实战，经过 9/8–9/13 多轮真实使用。
> 按工作区"证据驱动演进"规则，尚只在 1 个真实项目验证，固化为操作手册但标注 beta；
> 待第 2 个同类项目验证后再升级为 stable 并并入主流程。

---

## 什么时候用本层

命中以下任一情况，就应该加载本层，而不是只走通用流程：

- 一个竞赛任务要**跨多个 AI 工具/会话**完成（如 Codex、Astra、Doubao 分工），中途需要把上下文原样交给另一个模型；
- 赛题带**官方模拟器/在线接口**，有"演练无限次、正式测试仅 N 次"的机会约束，成绩只能来自真实响应；
- 子问题是**在线决策/策略算法**（控制器在只可见当前观测的条件下行动），需要离线裁判器做大规模验证；
- 指标有**硬安全约束**（如"必须 100% 清除"）与**效率目标**（如"平均 ≤X 秒/源"）的双重要求，二者不能互相稀释；
- 某个子问题**反复优化仍不达标**，团队怀疑"不是调参能解决"，需要先审计再动手；
- 论文里的每张图、每个数都要能回答"这是复算的、报告转述的，还是构造示例"。

纯数据分析、一次性建模、单会话能闭环的题目，用通用流程即可，不必启用本层。

## 贯穿全层的七条铁律（来自实战的最高优先级教训）

1. **官方条件与离线假设严格分开**。题目没承诺的随机分布、评分权重、数值标准，一律不得说成官方规定；离线分布必须显式标注为"模拟假设"。
2. **证据分级，按级措辞**。解析证明 ＞ 数值证书 ＞ 统计证据 ＞ 报告转述 ＞ 猜想。没有解析证明就不得写"严格全局最优/必然"，降级为"数值全局最优证书/数值观察"。
3. **两个世界物理隔离**。离线裁判器可以持有真值，控制器绝不允许读取；离线产物显著标 `OFFLINE`，正式成绩只能来自真实 HTTP 响应与官方日志。
4. **安全约束与效率目标分开汇报**。多局平均目标、任意布局最坏上界、单局门槛是三件事；不得用合并均值、P95 成功或挑案例来代替"必然清除"。
5. **不达标就显式标未达标**。目录可命名"未达标"，自检清单留空勾，正式测试表留空；宁可交一个诚实的基线，绝不伪造案例、数字、日志或"已修复"。
6. **换模型先交"证据边界"，不交"乐观结论"**。交接包必须包含当前状态、缺口、冲突、验收矩阵和独立复核记录，而不是只交一份"基本完成"的总结。
7. **数字必须可追溯到文件、命令、种子、算法版本、环境**。"代码可编译"不等于"算法正确"，"自建模拟器通过"不等于"官方已通过"。

## 与既有模块的关系

- 上游：`数学建模完整流程.md` 的阶段 1–7 产出模型与代码；本层在**复杂/在线/跨会话**条件下为这些阶段加操作约束。
- 并行：`core/runtime/` 的 v8/v9 证据链、`submission/gates/` 的 8 个门禁是**可执行生产系统**；本层是当无法端到端跑该系统（多工具、外部模拟器、人主导）时的**人工/对话等价规程**。两者理念一致：证据绑定、数字冻结、人工决策留痕、AI 合规披露。
- 下游：`论文生成流程.md`、`submission/` 负责成稿与门禁；本层的 [06](06_可复现论文图集流水线.md) 负责把"图"这一高频出错环节做成可复现流水线。
- 收尾：项目结束按 `standards/project_closure.md`（PCS）复盘，本层的手册即从复盘中沉淀。
