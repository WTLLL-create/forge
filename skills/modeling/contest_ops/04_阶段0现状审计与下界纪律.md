# 04 阶段0现状审计与下界纪律

> 解决的问题：当一个子问题反复优化仍离目标差一个数量级时，团队容易陷入"改参数碰运气"，
> 甚至用放松安全门限的方式假装修好。正确做法是**先停下来做阶段0审计**：认清现状、定位瓶颈、
> 分清"问题级下界"和"策略级下界"，再决定是改结构还是放弃，然后才进入优化。

---

## 1. 什么时候强制进入阶段0

命中任一信号，先审计、后优化：

- 指标离目标差 2 倍以上，且多轮参数微调没有数量级改善；
- 代码、文档、成绩三者对不上（版本号、骨架点数、阈值、命令行参数互相矛盾）；
- 出现"随机样本全成功但有人能构造出违规反例"（经验证据与完备性冲突）；
- 准备把一个"安全但慢"的基线交给下一个模型继续优化。

阶段0**只读 + 只新增审计产物，不改任何既有代码、不连正式系统**，并在报告里声明这一点。

---

## 2. 阶段0审计的固定内容

### 2.1 审计范围与可复现性
列出：代码（含备份版本）、文档、成绩（CSV/XLSX/日志，区分成功/失败局）、官方材料；
声明未连接在线系统、未修改既有代码、只新增剖析器与报告；统一 `PYTHONHASHSEED` 与固定种子，
给出剖析局数、场景分层与命令。

### 2.2 官方口径核对（独立时钟）
把官方计时/规则公式独立重写一遍，和自建模拟器对账。
- 实战：官方总时间 `T = 移动/5 + 5×检测 + 1×切频道 + 5×成功清除 + 3×扑空`；
  发现自建模拟器错误地让 `/clear` 切频道，单局多计 15 秒 → 主指标全部改用独立官方时钟重算。

### 2.3 代码/文档/成绩一致性核对
做一张多版本对照表（骨架、阈值、上限、标签、命令行参数、外点是否采用等），逐项指出矛盾。
实战中一次审计列出 7 类矛盾：文件头与实现不符、未使用的常量、版本号混用、复现实验导入错版本、
路线长度张冠李戴、引用的脚本未随包提供、启动脚本硬编码真实队号。

### 2.4 完备性审计（反例优先）
逐条列"风险 / 证据 / 硬约束影响 / 阶段1要求"。
- 实战：探针预算耗尽后按 40m 清除（官方只保证 20m）→ 可构造半径 30m 的反例，**足以否决"0 扑空程序级保证"**；
  环形兜底原地重测、步长与证明不符、"80 步上限"可累加到 240 步、离散网格代替连续证明等。
- 明确写出："样本全成功证明的是这些样本通过，不消除程序级反例"。

### 2.5 真实成绩复核
对历史真实尝试逐局重算 mean/median/P95/worst 与网络失败率；
**用独立计算纠正转述错误**（实战：速览写"中位数 652"，原始文件精确值 641.96）；
对失败率给置信区间（如 58 成功/3 失败，点估计 4.92%，Wilson 95% 区间 1.69%–13.49%），
并估算"三次正式机会至少失败一次"的概率，论证网络加固的必要性。

### 2.6 大样本离线剖析（独立时钟）
分层场景（随机混合 / 贴边全定向外向 / 贴边半定向外向）× N=10..16，固定种子；
报告全清率、判空正确性、扑空、最大清除距离、以及**按动作成本拆分的时间预算占比**，据此排序瓶颈。
- 实战：骨架移动 46.9% + 骨架共享检测 24.1% 合计 71%，兜底类合计 <2% → 主要矛盾是骨架路线与共享检测，
  不是罕见兜底；这直接否定了"继续优化兜底参数"的方向。
- 同种子两次运行逐动作时间线逐字段一致，作为确定性复现检查。

### 2.7 可达性审查（下界纪律，见第 3 节）

### 2.8 优化清单与消融顺序
按 P0/P1/P2 列表，每项给"原理与预期收益 / 完备性影响 / 消融方法"：
- P0 正确性修复（统一 ≤20m 清除门限、全局动作去重、独立时钟修模拟器）；
- P1 结构性改动（新骨架、自适应外点、搜索定位合并、尾段收束）；
- P2 调度优化；P3 概率提速（默认关闭，单独报告漏检上界，只有用户显式选择才启用）。
- 严格"**一项改动、一组单测、一轮小消融、一轮压力回归**"，任一安全指标恶化立即回滚。

### 2.9 放行条件（阶段0 → 阶段1）
明确多少局可行性、多少压力局、官方逐动作对账、确定性复现、墙钟检查全部通过后，才允许声称 100%；
效率目标只按最终实测 mean/p50/p95/worst 判定，不用文档推测替代；并先建立可回滚基线（Git 或副本）。

## 3. 下界纪律（防止"不可能"与"已最优"两种谎言）

严格区分四类，绝不混用：

| 类别 | 含义 | 实战例子 |
|---|---|---|
| 严格几何/动作下界 | 对**所有**合法算法成立的连续域/动作必要成本 | 外部单点对边界 R=1000 定向源最大覆盖角宽 ≈58.11°，至少需 7 个外部方位 |
| 依赖分布的期望下界 | 假设了随机分布才成立，必须标注分布 | 离线分布下的期望路程 |
| 已知真值的可行路线参考 | 用了控制器不可见的真值，只能作参考上界 | 2-opt 求出的已知坐标路线——**不是最优路线，也不是严格下界** |
| 启发式估计 | 经验值，不能当定理 | 历史 282/260 等数字不得照搬为定理 |

规则：

1. **问题级下界与策略级下界分开**："固定 31 点全访至少 754 秒/源"只否定 31 点全访这一**架构**，
   不证明所有自适应策略都达不到 300；"必须绕整圆所以至少走周长"把周长当必经距离是错的
   （点之间可走弦、可穿圆内、可依响应自适应）。
2. **下界不得因共享路段重复相加**；宽松下界只用于排除不可能性，算不出"伪精确的最优安全策略上界"。
3. 当宽松下界（如 262.95 秒/源）低于目标（330）时，结论是"**未被下界排除，但是极紧的研发目标**"，
   既不能写"几何上不可能"，也不能写"应该能达到"。
4. 给区间而非单点："宽松问题级下界 → 当前已验证策略实测值"，并注明中间尚无证据。

## 4. 阶段0报告的骨架

```
1. 结论先行（能不能进正式测试/能不能声称达标；硬约束违规；最有希望的路线）
2. 审计范围与可复现性
3. 官方规则最终口径（独立时钟）
4. 当前算法复述（状态机/骨架/定位/兜底/清除判空）
5. 多版本代码与文档一致性核对（表 + 矛盾清单）
6. 已完成的基础检验
7. 完备性审计（风险/证据/硬约束影响/修复要求 表）
8. 真实成绩复核（分档统计 + 失败率置信区间）
9. 阶段0离线剖析结果（分层表 + 时间预算占比 + 确定性复现）
10. 可达性审查（问题级 vs 策略级下界 + 骨架结构比较）
11. 优化清单与消融顺序（P0/P1/P2）
12. 网络加固方案
13. 阶段0放行条件
```
