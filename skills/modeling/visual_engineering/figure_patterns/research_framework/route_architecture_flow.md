# 技术路线图 / 模型框架图 / 算法流程图

> 论文前三张最重要的图：路线图告诉评委"你在做什么"，框架图告诉评委"你的方法怎么构成的"，流程图告诉评委"你的算法怎么运行的"。

---

## Pattern F-001：技术路线总览图

### 适用场景
所有论文的第一张图，放在问题分析末尾或模型建立开头。评委用 30 秒看完这张图就应该理解你的研究框架。

### 想证明什么
"我的研究不是随机尝试，而是有一条清晰的、有逻辑的路线。"

### 结构设计

```
┌─────────────────────────────────────────┐
│              研究问题                      │
│   [一句话核心问题]                          │
└─────────────────┬───────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│           阶段一：数据审计与问题诊断         │
│  缺失值分析 → 右删失检测 → 工况识别          │
│  → 输出：数据质量报告 + 关键发现             │
└─────────────────┬───────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│           阶段二：代理模型建立               │
│  按工况分群 → 独立训练RF → 交叉验证          │
│  → 输出：各工况的排放-功率映射函数            │
└─────────────────┬───────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│           阶段三：多目标优化                │
│  NSGA-II搜索 → Pareto前沿 → 膝盖点分析      │
│  → 输出：最优控制策略 + 决策建议             │
└─────────────────┬───────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│           验证与建议                        │
│  消融实验 → 敏感性分析 → 推广性讨论           │
└─────────────────────────────────────────┘
```

### 设计要点

| 要素 | 要求 |
|------|------|
| 层数 | 3-5层，每层=一个研究阶段 |
| 箭头 | 单向（从上到下），不要有循环箭头（那是流程图的事） |
| 每层内容 | 输入→处理→输出，三位一体 |
| 颜色 | 不超过3色，每层一色或关键路径一色 |
| 标注 | 每层标注对应的论文章节号 |
| 字数 | 每层不超过3行描述 |

### 常见错误

| 错误 | 为什么错 | 修正 |
|------|----------|------|
| 流程太细（10+层） | 失去总览功能 | 合并为3-5个阶段 |
| 只有操作没有输出 | "做了什么"没有"产出什么" | 每层标注输出 |
| 没有标注章节号 | 图和正文脱节 | 标注"§2""§3""§4" |
| 箭头双向或循环 | 路线图是线性结构 | 循环放流程图 |
| 装饰元素过多 | 干扰信息 | 去掉阴影/渐变/3D |

### 论文解释模板

```
图1展示了本文的研究技术路线。
研究分为三个阶段：数据诊断（§2）→ 代理建模（§3）→ 多目标优化（§4）。
三个阶段之间存在严格的因果依赖：
阶段一的诊断结果（右删失+工况差异）驱动了阶段二的模型设计；
阶段二的代理函数使阶段三的优化可行。
```

## Pattern F-003：模型架构图

### 适用场景
模型相对复杂（多组件/分层/多输入输出），需要一张图解释"模型内部怎么组织的"。

### 想证明什么
"我的模型不是黑箱，它的每个组件都有明确的功能和设计理由。"

### 结构设计

```
         ┌──────────────┐
         │  输入层         │
         │  x₁, x₂, ... xₚ│
         └───────┬──────┘
                 ↓
    ┌────────────┼────────────┐
    ↓            ↓            ↓
┌────────┐ ┌────────┐ ┌──────────┐
│时间特征  │ │统计特征  │ │物理特征   │
│Lag 1-3 │ │Rolling │ │工况标签   │
│差分     │ │均值/方差│ │约束编码   │
└───┬────┘ └───┬────┘ └────┬─────┘
    └────────────┼────────────┘
                 ↓
         ┌──────────────┐
         │  核心模型      │
         │  RF / XGBoost │
         └───────┬──────┘
                 ↓
    ┌────────────┼────────────┐
    ↓                         ↓
┌──────────┐          ┌──────────────┐
│ 预测输出   │          │ 可解释性分析   │
│ ŷ(x)     │          │ SHAP / 重要性  │
└──────────┘          └──────────────┘
```

### 设计要点

- 输入→处理→输出，三明治结构
- 每个模块标注"维度/参数量"（如"Lag-3, 3特征"）
- 用不同颜色区分：输入层/特征层/模型层/输出层
- 箭头标注数据流向（不是算法流向）

### 论文解释模板

```
图X展示了本文提出的 [模型名] 的整体架构。
模型由 [N] 个功能模块组成：
(1) [模块A]：负责 [功能A]，将 [输入] 转化为 [输出]；
(2) [模块B]：基于 [模块A的输出]，实现 [功能B]；
...
模块间的数据流为 [A→B→C]。
```

## Pattern F-004：算法流程图

### 适用场景
算法有明确的步骤、判断分支或循环结构（GA/NSGA-II/MIP/Monte Carlo/迭代求解）。

### 想证明什么
"我的算法每一步都有明确的目的，收敛/终止条件有依据。"

### 结构设计

```
              开始
               ↓
    ┌──────────────────────┐
    │  初始化                │
    │  参数/种群/初始解       │
    └──────────┬───────────┘
               ↓
    ┌──────────────────────┐
    │  适应度评估            │
    │  约束可行性检查         │
    └──────────┬───────────┘
               ↓
         ┌────┴────┐
         │ 收敛？   │───是──→ 输出最优解
         └────┬────┘
              │否
              ↓
    ┌──────────────────────┐
    │  遗传操作              │
    │  选择 → 交叉 → 变异    │
    └──────────┬───────────┘
               ↓
    ┌──────────────────────┐
    │  新一代种群            │
    └──────────┬───────────┘
               ↓
           (回到评估)
```

### 设计要点

| 要素 | 规范 |
|------|------|
| 矩形框 | 操作/步骤 |
| 菱形框 | 判断/分支（唯一使用菱形的场景） |
| 箭头 | 单向，标注条件（如"是/否""通过/未通过"） |
| 循环 | 箭头回到上游，形成闭环 |
| 终止 | 标注终止条件和输出 |
| 参数标注 | 在关键步骤旁标注参数值（如"N_GEN=100"） |

### 论文解释模板

```
图X展示了 [算法名] 的执行流程。
算法从 [初始状态] 开始，经过 [主要步骤] 的迭代。
收敛判据为 [条件描述]，当 [条件满足] 时算法终止，
输出 [最终结果]。
```
