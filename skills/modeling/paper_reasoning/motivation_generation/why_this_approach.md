# 为什么采用这个方案（Why This Approach）

> `why_this_model.md` 解决单个模型的选择理由。
> `why_this_improvement.md` 解决单个模型为什么需要改进。
>
> 本文件解决更上层的问题：**整个方案的架构为什么是现在这样？**
>
> 不是「为什么用 KMeans + RF + NSGA-II」，而是「为什么是聚类→代理→优化的三阶段架构」。

---

## 一、为什么需要这一层论证

大多数论文只论证了"每个模型为什么选"，但没论证"模型之间为什么是这样连接的"。

评委看到的常见现象：

```
模型A选得好 ✓
模型B选得好 ✓
模型C选得好 ✓
但A→B→C的串联逻辑：没说 ✗
```

**这就是「做了实验然后找理由解释」和「因为研究问题所以设计实验」的区别。**

## 二、方案论证的四层框架

### 层 1：问题结构决定了方案的顶层架构

```
问题的数学结构：[描述]
    ↓ 决定了
方案必须是什么样的：[顶层约束]
    ↓ 因此
方案架构：[顶层架构图]
```

**示例**：

```
水泥窑优化问题的数学结构：
- 多工况（非单一状态）→ 方案必须是状态感知的
- 黑箱关系（无解析式）→ 方案必须依赖代理模型
- 多目标冲突 → 方案必须支持 Pareto 分析

因此，方案必须是：状态识别 → 代理建模 → 多目标优化 的三阶段架构。
任何缺少其中一环的方案，都不完整。
```

### 层 2：架构的每一层对应问题的一个挑战

```
挑战1：[问题中的具体困难] → 需要架构中的 [层A] 来解决
挑战2：[问题中的具体困难] → 需要架构中的 [层B] 来解决
挑战3：[问题中的具体困难] → 需要架构中的 [层C] 来解决

架构 = 挑战的镜像。架构的层数 = 问题的独立挑战数。
```

**示例**：

```
挑战1：54.7%排放数据右删失，标准回归失效
  → 层A：右删失诊断与校正

挑战2：不同工况下排放-功率关系差异显著
  → 层B：工况自适应代理建模

挑战3：排放-功率-成本三者不可兼得
  → 层C：多目标Pareto优化

三层架构是对三个独立挑战的一一回应。
不是随机堆砌，而是问题驱动的架构设计。
```

### 层 3：层与层之间的依赖关系是有方向的

```
层A → 层B：因为 [层A的结论]，所以需要 [层B做什么]
层B → 层C：因为 [层B的结论]，所以需要 [层C做什么]

如果调换顺序会怎样？→ 证明顺序的不可逆性
```

**示例**：

```
层A（诊断）→ 层B（代理）：
  因为右删失诊断揭示54.7%数据不可靠，
  所以代理模型必须使用考虑删失的Tobit回归，
  而非标准OLS回归。

层B（代理）→ 层C（优化）：
  因为代理模型将复杂的排放-功率关系压缩为可快速评估的函数，
  所以优化器可以在代理函数上高效搜索，
  而非在真实系统（不可行）或原始数据（太慢）上搜索。

如果先优化再代理？→ 优化没有可评估的目标函数，不可行。
如果先代理再诊断？→ 代理模型建立在错误（右删失未处理）数据上，不可靠。
```

### 层 4：方案有备选架构，当前方案是最优的

```
备选方案1：[描述] → 为什么不选：[理由]
备选方案2：[描述] → 为什么不选：[理由]

当前方案在 [维度A] 和 [维度B] 上优于备选方案，
在 [维度C] 上略逊于备选方案2，
但 [维度C] 在此问题中不是最关键的，
因为 [理由]。
```

## 三、常见方案架构模式及其论证

### 模式 1：顺序流水线（A → B → C）

**适用**：前后步骤有严格的因果依赖

**论证焦点**：为什么顺序不可逆？

```
流水线：数据清洗 → 特征工程 → 模型训练 → 结果分析

为什么不可逆：
- 未经清洗的数据喂给特征工程 → garbage in garbage out
- 特征工程未完成就训模型 → 模型学的是噪声
- 没有模型就没有结果分析的基础
```

### 模式 2：并行竞争（A || B || C → 选最优）

**适用**：不确定哪个方法最好，需要实验比较

**论证焦点**：为什么需要并行比较而不是直接选一个？

```
为什么不能直接选：
- 方法A的理论假设在本题上可能不成立
- 方法B的优势在本题条件下可能被削弱
- 没有先验知识确定哪个最好

因此采用并行竞争策略：同时运行A/B/C，通过实验确定最优。
这本身就是一个科学发现的过程——不仅仅是"用了最优模型"，
而是"发现了在此条件下哪个模型最优"。
```

### 模式 3：分层递进（粗→细→精）

**适用**：问题有天然的多尺度或多层次结构

**论证焦点**：为什么不能一步到位？

```
直接精细建模的问题：
- 搜索空间太大 → 计算不可行
- 局部最优陷阱 → 结果不可靠

分层递进的优势：
- 粗层：缩小搜索范围，确定全局结构
- 细层：在缩小后的空间中精确定位
- 精层：用最精确的模型验证最终方案

每层解决一层的问题，复杂度被逐层分解。
```

### 模式 4：机理+数据混合（物理骨架 → 数据校正）

**适用**：问题有部分已知物理规律，但不足以完全建模

**论证焦点**：为什么纯机理不行、纯数据也不行？

```
纯机理模型的问题：
- [某个子过程] 的物理机制未知
- 参数无法全部从第一性原理确定

纯数据模型的问题：
- 缺乏物理约束会产生不合理的输出
- 外推能力受限

混合模型 = 已知的部分用物理方程（保证合理性）
        + 未知的部分用数据模型（保证灵活性）
        + 两者通过 [耦合机制] 连接
```

## 四、方案论证的论文表达对照

### ❌ 无方案论证（低分）

```
"本文的建模流程如下：
1. 数据预处理
2. K-means聚类
3. 随机森林预测
4. NSGA-II优化"
```

→ 读起来像操作步骤，不像研究方案。

### ✅ 有方案论证（高分）

```
"本题的建模面临三个递进的挑战：
挑战1（数据层面）：右删失导致标准回归失效；
挑战2（建模层面）：工况差异使单一代理模型不可靠；
挑战3（决策层面）：多目标冲突需要Pareto权衡分析。

这三个挑战之间存在因果依赖关系：
不解决挑战1，挑战2的代理模型建立在错误数据上；
不解决挑战2，挑战3的优化没有可评估的目标函数。

因此，本文的方案架构是对这三个挑战的逐层回应：
第一层诊断右删失，指导数据校正；
第二层建立工况自适应代理模型，将对复杂系统的评估压缩为可计算函数；
第三层在代理函数上进行多目标优化，揭示Pareto前沿。

三层之间的关系不是并列的，而是：
诊断→指导代理建模→代理建模→使优化可行。
任何一层缺失，整个方案将失效。"
```
