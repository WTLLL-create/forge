# Architecture Expression Template — 架构类论文章节模板

> Stage 20.6: 当建模不是单一模型而是架构模式时，论文应有对应的章节结构。

## 何时使用

Router 输出了 `architecture_patterns` (非空) → 使用此模板而非标准单模型章节。

## N.X 模型建立（架构视角）

```
N.X.1 整体技术路线
  展示: 从数据→特征→候选模型→对比→选择/集成的完整路线图
  说明: 为什么这个架构适合本题的问题结构
  图表: 技术路线流程图

N.X.2 数据融合与特征工程
  多源数据如何合并 (data_fusion/multi_source_merge.md)
  构造了哪些特征及理由 (feature_eng/)
  特征筛选方法和结果

N.X.3 候选模型构建
  每个候选模型: 简要原理 + 为什么入选 + 参数设置
  不用逐个详细介绍——对比表中会展示结果
  如果是分而治之架构: 论证子问题独立性的合理性

N.X.4 模型对比与选择
  对比表: 模型 | RMSE | MAE | R² | 排名 | 优势 | 劣势
  不只给数字: 分析"为什么A在这项指标上优于B"
  差异性分析 = 论文的思考深度

N.X.5 集成优化（可选, 如果用ensemble）
  集成策略 (Stacking/加权平均)
  集成后性能 vs 单模型最优
```

## 对比：标准 vs 架构

| 标准模板 (单模型) | 架构模板 (多模型) |
|------|------|
| N.X.1 建模思路 | N.X.1 整体技术路线 |
| N.X.2 决策变量定义 | N.X.2 数据融合与特征工程 |
| N.X.3 目标函数 | N.X.3 候选模型构建 |
| N.X.4 约束条件 | N.X.4 模型对比与选择 |
| — | N.X.5 集成优化 |

## 论文叙事重点

不是"我用了XGBoost，效果很好"。
而是"我设计了这样一个架构，通过系统对比证明了XGBoost是最优选择，而且我理解为什么它最优。"
